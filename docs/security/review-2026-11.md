# Internal security review, November 2026

This is a summary of the maintainers' own security review of Taskcell. It is not a third-party audit.

## Method

- **Scope:** the whole repository at `dde684b` (7 November 2026): the CLI, the factory runners, the sandbox, the Hub server and the desktop app.
- **How:** a multi-agent review. Claude Opus agents hunted for vulnerabilities and checked coverage (26 agents), and every candidate was verified independently by Claude Fable before it counted as a finding (46 verifications).
- **Proof:** findings were reproduced in a locked-down Docker harness (no network, empty environment, read-only source, resource limits) with dummy repositories and dummy credentials. Nothing ran against a live service.
- **Threat model:** the agent is hostile. Most findings start from code or text the agent writes inside the sandbox.

Two smaller scoped reviews ran before it; their confirmed findings were fixed and re-checked in this one.

## Result

14 confirmed findings: 2 high, 9 medium, 3 low. Nothing found lets an unauthenticated remote attacker run code. Both high findings start from the sandboxed agent.

13 are fixed on `main` and shipped in 1.13.0; the last, C13 (low), is fixed in 1.16.1. All 14 are fixed.

| ID | Severity | Finding | Fixed in |
|---|---|---|---|
| C1 | high | Git hooks written by the agent could run on the host during commit | [#596](https://github.com/spietrza/taskcell/pull/596) |
| C2 | high | A sandboxed agent could read the Hub token and call the Hub as the operator | [#597](https://github.com/spietrza/taskcell/pull/597), [#605](https://github.com/spietrza/taskcell/pull/605) |
| C3 | medium | Session id path traversal in session capture and restore | [#601](https://github.com/spietrza/taskcell/pull/601) |
| C4 | medium | Linear comments from integrations were trusted as member comments | [#599](https://github.com/spietrza/taskcell/pull/599) |
| C5 | medium | Every GitLab commenter was trusted for spec and readiness gates | [#599](https://github.com/spietrza/taskcell/pull/599) |
| C6 | medium | Run transcripts were only pattern-masked before the CI artifact upload | [#602](https://github.com/spietrza/taskcell/pull/602) |
| C7 | medium | The outgoing-diff secret gate skipped files marked binary in `.gitattributes` | [#602](https://github.com/spietrza/taskcell/pull/602) |
| C8 | medium | A repository config value reached a shell command in the desktop app | [#600](https://github.com/spietrza/taskcell/pull/600) |
| C9 | medium | Doc chat could send the operator's credential to a repository-chosen URL | [#600](https://github.com/spietrza/taskcell/pull/600) |
| C10 | medium | Host writes under `.vanguard` followed symlinks committed to the repository | [#601](https://github.com/spietrza/taskcell/pull/601) |
| C11 | medium | A Projects board item from another repository ran a local issue | [#599](https://github.com/spietrza/taskcell/pull/599) |
| C12 | low | Failure comments posted agent CLI output without redaction | [#602](https://github.com/spietrza/taskcell/pull/602) |
| C13 | low | The verify gate runs in a login shell inside the sandbox, so the agent can plant a profile that forges a PASS | fixed in 1.16.1 (#1180, PR_LINK) |
| C14 | low | Research, spec and review comments skipped exact-value credential redaction | [#602](https://github.com/spietrza/taskcell/pull/602) |

C13 was low because PR review and the repository's own CI still check every change; a forged local PASS does not reach `main` by itself. The fix runs the verify command in a non-login shell that reads only the root-owned `/etc/profile`, never the agent-owned `$HOME/.profile`; agent CLIs keep the login shell for PATH setup.

Further hardening from the same review: [#607](https://github.com/spietrza/taskcell/pull/607) (sandbox egress and delivery), [#608](https://github.com/spietrza/taskcell/pull/608) (prompt context and trust checks), [#603](https://github.com/spietrza/taskcell/pull/603) (least-privilege CI token), [#604](https://github.com/spietrza/taskcell/pull/604) (pinned image dependencies).

## Not covered

- Live GitHub, GitLab and Linear settings, secret scopes and branch protection, which source code cannot show.
- The Hub server mode, sign-in and teams added in 1.16.0 came after this review.
